# レビューと受け入れの運転規約

LLM に実装させた道具をどう受け入れるかの規約。実績で再発を止めたものだけを残し、6 項目で
運転する。根拠と経緯は `docs/adversarial-loop-meta-evaluation.md`、旧版 (509 行) は git 履歴。

1. **実装前に発注側が書く**: 契約 (目的・用途内外・入出力と exit・不変条件・所有点、10〜30 行)、
   受け入れ test、固定 4 変異 (不正入力の置換 / 境界の反転 / 出力 marker・counter の増減 /
   正規化の除去)。書けなければ発注しない。既存の正本と既製の道具を先に読む
2. **構造を先に決める**: 不変量が複数 site に配られる、または状態 × 遷移を列挙できないなら、
   funnel か enumerator を先に作るか用途を縮小する。局所 patch は発注しない
3. **初回レビューは read-only の品質推定**: 道具本体だけを渡し (発注書・過去の指摘・裁定は
   見せない)、correctness と要件に効く指摘だけを求める。finding は class でまとめ、処置は
   仕様縮小 → 削除 → 既存 primitive への集約の順。新機構は fix でなく別発注
4. **fix は 1 回**: 同 round に発注側の failing repro・変異器・独立 reviewer を入れる。自己申告と
   test 本数は証拠にしない。fix diff ≤ 100 行、発注書 ≤ 60 行、レビュー単位 ≤ 400 行
5. **採否は用途内 P0 と変異の生存数で決める** (生存 0/4 が受け入れ条件)。緑と指摘総数は補助。
   直さない指摘は転記しない — reviewer の報告書 file がそのまま記録
6. **最大 3 巡で止める** (基準品質 → class fix 1 回 → 独立再確認 1 回)。再確認で P0 なら
   4 巡目を回さず、閉じた選択肢から人間が選ぶ: 削除・縮小 / 契約の訂正 (test を先に直して
   再入場、巡数は 1 から) / 構造化 (funnel・enumerator を別発注) / bounded-risk 受入 / 廃棄。
   「同じ artifact へもう 1 巡 patch」だけが選択肢に無い

この規約への追記は禁止し、削除だけを許す。足したいものが出たら、先に何を消すかを書く。
