# 注入 corpus の基礎表

改造が新しい欠陥をどれだけ作り込んだかを、回帰 filter の報告書 11 通から機械的に集計した
台帳。 目的は「gate で捕まえた」と「そもそも入らなかった」を分離し、発生率を下げる方策を
選ぶ材料にすること。

集計日 2026-08-25。 出典は `drafts/gates/` と `drafts/ruling61/` の
`*regression-review*.md` 11 通 (各巡の題名・`VERDICT:` 行・所見見出し)、各巡の発注書の
`## 修正方式` 節、および `*-gates.log` 9 通。

## 表 B — 起源 class 別の内訳

class は方法論 §7.3 が既に使っている下位観点に合わせた。 25 件すべてを所見見出しの記述から
1 件ずつ割り当てている。

| 起源 class | 件数 | 代表例 |
|---|---|---|
| 対 site の片側 fix | 5 | 撤去した baseline の 2 度読みと、それに依存した stall 断定が対で残った |
| 契約転写の乖離 | 5 | 書き直した宣言文 / docstring / latch の説明が実装と食い違う (3 巡で再発) |
| 到達性の変化 | 4 | fail-closed 化の置換で既存 deny 3 系統が到達不能になった |
| test の共犯化 | 4 | 担保 test 名を無関係な test に付け替えて台帳照合を緑に保った |
| 新設分岐・資源の failure-mode 不足 | 4 | 新 family が「ユーザー発話でないもの」に発火する |
| 兄弟 site の掃引漏れ | 1 | 否定 lookahead を片側だけ拡張し metadata が誤申告になった |
| 精度前提の転移 | 1 | 遅延描画で表示値の観測時刻が判定 poll から 1 cadence ずれる |
| 表層品質 | 1 | 日本語 file への英語 docstring 混入と helper の複製 |

上位 5 class で 22/25 (88%)。 §7.3 が r54–r76 era の 12 件で出した分布 (failure-mode 不足 4 /
境界条件の未掃引 4 / 転写ミス 1 / 境界的 3) と比べると、**転写の乖離が 1 → 5 に増えて単独 2 位に
上がり、逆に境界条件の未掃引が 4 → 1 に落ちている**。 この era の fix は「既存の言葉を書き直す」型を
多く含み、書き直しの片側だけが実装に届いていない。

## 表 C — 「gate で捕まえた」と「そもそも入らなかった」の分離

| 区分 | 巡数 | 注入件数 | 該当巡 |
|---|---|---|---|
| gate で捕まえた | 6 | 25 | fix 9 / fix 10 / fix 11 / 構造巡 / 構造巡 + fix 6 / warn family |
| そもそも入らなかった | 5 | 0 | fix 12 / fix 7 / fix 8 (r81) / 否定断定語彙拡張 / send-gate |

分離の要点が 2 つある。

**1. 決定的 gates は注入を 1 件も捕まえていない。** `*-gates.log` 9 通に残る非ゼロ exit は
4 件で、内訳は新規 module の未実装 red 1・TDD の red 相 2 (r78 の red 確認、r79 の regression
red)・`ty` の既知 1 件。 どれも注入の検出ではない。 つまりこの era の注入 25 件は**全数が
LLM 層でしか捕まらなかった**。 安い網から高い網へ、という §7.3 の並べ方は正しいが、
安い網の目にはこの class が掛からない。

**2. 注入ゼロの fix 巡は、いずれも `既存集約` を 1 件も含まない。** fix 12 は削除のみ、
fix 8 は削除 + 機構追加。 逆に `既存集約` を含む fix 巡は **5 巡とも 1 件以上注入している**
(8 / 3 / 2 / 7 / 1)。 fix 7 は発注書が現存しないため方式を確認できていない。

## この表から立つ仮説と、次に取る計測

仮説: **注入率は「触る量」より「修正方式」に連動し、`既存集約` が最も高い**。
方法論 §7.3 の優先順 (仕様縮小 → 削除 → 既存集約 → 機構追加) は注入率の順ではない。

この表だけでは断定できない。 集計が巡単位なので、1 巡に複数方式が混ざるとき**どの所見の
修正が注入したかを分離できていない**ためである。 §7.3 の r54–r76 監査は commit hunk まで
遡って 12 件を型に割り当てており、同じ粒度が要る。

次に取る計測は **注入 25 件の hunk 遡及** — 各注入を、それを生んだ fix 所見とその所見の
宣言方式に結び付ける。 これで方式別の注入率が巡単位から所見単位になり、上の仮説が支持されるか
反証されるかが決まる。
